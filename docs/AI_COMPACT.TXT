QUAS — AI COMPACT REFERENCE
Engine: quas.js v1.0 (fork of jcss). Runtime CSS engine, Tailwind CSS v4 compatible, v3 class names still work.
Read this file fully before writing any markup that uses Quas. Everything below was verified in headless Chromium.

================================================================================
0. WHAT IT IS (30 seconds)
================================================================================
- ONE JS file. No build step, no CSS file, no config needed.
- At runtime it reads class="" attributes from the live DOM, generates CSS for each class it understands,
  and writes it to <style id="q-css-utilities">. Unknown classes (your own: "card", "modal") are ignored silently.
- Write class names EXACTLY like Tailwind v4 docs. Do not invent names.
- Dynamic classes work (`bg-${c}-500` is fine) as long as the final string reaches the DOM. No source scanning.
- Extras: scoped component CSS (<css> tag / Quas.css) and an extension API.
- Internal CSS variables use the prefix --q-* (NOT --tw-*). Never write --tw-* in arbitrary values.

================================================================================
1. CONNECT
================================================================================
<head>
  <script>window.Quas = { /* optional, see section 2 */ };</script>   <!-- must come BEFORE quas.js -->
  <script>window.tailwind = { config: { theme: { extend: { /* optional, section 8 */ } } } };</script>
  <script src="https://cdn.jsdelivr.net/gh/wemmbley/quas@2.x/dist/quas.min.js"></script>
  <script src="https://cdn.jsdelivr.net/gh/wemmbley/quas@2.x/dist/quas-debug.min.js"></script>
</head>

- Quas debug not required, only for dev mode to maintain css conflicts and safari browser support css mistakes.
- Plain <script> in <head> (it appends <style> tags to document.head). Load it once per page.
- Elements added later (JS, innerHTML, fetch partials, frameworks) and later class changes are picked up
  automatically by a MutationObserver (async, ~1 tick). For an immediate result call Quas.scan(root).
- Laravel/Blade: put the script tags in the layout header partial. Blade output is fine: scanning happens on the rendered DOM.
- Injected automatically: Tailwind v4 preflight (<style id="q-css-preflight">: resets, .container, keyframes
  spin/ping/pulse/bounce/fade, :root{--spacing:.25rem; --font-sans/--font-serif/--font-mono}),
  and a first-paint "no transitions" override that is removed ~1 frame after load.
- Browser support: Chrome 111+, Safari 16.4+, Firefox 128+ (uses oklab gradients, rgb(from ...), :where, @container, color-mix).

================================================================================
2. OPTIONS (set on window.Quas BEFORE the script; all optional)
================================================================================
CSSClassMode   true   scan class attributes + observe changes. false = only Quas.processClasses/scan work.
CSSTagMode     true   process <css> tags (section 7).
CleanDOM       true   replace a processed <css> tag by an empty comment (false = keep it, hidden).
CSSWarnings    true   console.warn for unknown variants/values/utilities. false = silent.
                      Or a function (token, message) => boolean; return true to print.
CSSPerformance true   console.debug timing per scan.
CSSNonce       auto   nonce for injected <style> (defaults to the nonce of quas.js's own <script>).
AutoDarkMode   true   toggles class "dark" on <html> from prefers-color-scheme (live). false = you control it.
LegacyV3       false  true = Tailwind v3 values for the ones that differ (section 9).
cssExtensions  []     extension objects (section 8).

================================================================================
3. JS API
================================================================================
Quas.processClasses("p-4 hover:bg-red-500" | iterable)   register classes, regenerate CSS now.
Quas.scan(rootNode = document)                           collect classes under a (detached/new) node and register them.
Quas.css(text, id?)  /  Quas.css`...`                    register scoped CSS (syntax: section 7); returns scope class "q-css-N"
                                                         (or "q-css-<id>"). Add that class to the element that owns the styles.
Same text => same scope (anonymous scopes are deduplicated). Named ids (/^[\w-]+$/) are updated in place.
Generated utility CSS is never removed when a class disappears (harmless).
Dark mode: `dark:` = selector `html.dark .x`. Manual control: Quas.AutoDarkMode=false, then
document.documentElement.classList.toggle('dark').

================================================================================
7. SCOPED COMPONENT CSS  (<css> tag, Quas.css)
================================================================================
Put <css> as a CHILD of the element that owns the styles. Quas compiles it, adds class "q-css-N" to the PARENT, removes the tag.
<div class="p-4">
  <css id="card">                      <!-- id optional: [\w-]+, gives stable scope class q-css-card -->
    & { border-radius: 12px; }         native block. `&` = the scope root (the parent element)
    h2: text-xl font-bold;             rule: "selector: utilities;"  (selector scoped under the parent; space after the colon is REQUIRED)
    h2:hover: text-brand;              line prefixes after the selector are variants applied to every utility on the line
    p:dark: text-white;
    a:md:hover: underline;
    ::after { content: ''; }           selectors starting with :: attach to the root
    // comments, /* comments */, <!-- comments -->
  </css>
  <h2>Title</h2><p>Text</p><a href="#">Link</a>
</div>
Equivalent JS:  el.classList.add(Quas.css(`h2: text-xl;`, 'card'))   or   Quas.css`h2: text-xl;`
Rules: no nested rules, no @media/@supports blocks inside <css> (use md:/supports-[...] line prefixes instead).
       Component CSS is inserted BEFORE utilities, so utility classes win on equal specificity.
       group-*/peer-* variants work inside scopes. Selectors like html/body/:root cannot match from inside a scope (a warning is printed; use &).

================================================================================
8. CUSTOMIZING  (all before the script loads)
================================================================================
A) tailwind.config compatibility (window.tailwind.config.theme.extend):
   colors:     { ink: '#112233', brand: { DEFAULT: '#ff5fa8', dark: '#6a1b7e' } }   -> bg-ink, text-brand, text-brand-dark. ONLY #rgb/#rrggbb.
   boxShadow:  { neon: '0 0 20px #f0f' }  -> shadow-neon        (DEFAULT -> bare `shadow`)
   fontFamily: { display: ['Inter','sans-serif'] } -> font-display
   Anything else in the config is ignored.
B) Extensions (more power): window.Quas = { cssExtensions: [ { colors, utilities, prefixes } ] }
   colors     same format as above.
   utilities  deep-merged into the built-in utility tree. A node is:
                'name': 'css declarations string'                         -> .name { ... }
                'name': { $prop:'css-prop' | ['a','b'], key:'value', ..., $num:fn, $arbitrary:true|fn, ... }
              meta keys: $prop (css property or array)   $values (array/object of allowed keywords)   $num (fn: bare number -> value)
                         $frac (fraction support)   $arbitrary (true = raw value, or fn(value, ctx))   $color (fn(colorName, opacity, ctx) -> value)
                         $default (fn(valuePart, ctx))   $negative (allow -name)   $base (zero-specificity declarations)
                         $inherit (meta keys children inherit)   $selector (selector handler)
              ctx is mutable: ctx.$prop = '...' re-targets the property; ctx.$hint = type hint if one was given.
   prefixes   { name: { type:'pseudo', handler: selector => newSelector } | { type:'wrapper', handler: rule => `@... {${rule}}` } }
   Example:
     window.Quas = { cssExtensions: [{
       colors: { brand: '#ff5fa8' },
       utilities: {
         'text-stroke': { $prop:'-webkit-text-stroke-width', $num: v => v + 'px', $arbitrary: true, 'none': '0' },
         'glass': 'backdrop-filter: blur(12px); background: rgb(255 255 255 / 0.08)'
       },
       prefixes: {
         'selected': { type:'pseudo',  handler: s => s + '[data-selected]' },
         'ios':      { type:'wrapper', handler: r => `@supports (-webkit-touch-callout: none) {${r}}` }
       }
     }] };
   -> class="text-stroke-2 glass selected:underline ios:p-2".
   Extension utilities are emitted after built-ins, so they win equal-specificity conflicts (e.g. glass's background beats bg-brand).

9. v4 vs v3  (v4 is the default; v3-only classes keep working)
================================================================================
Still valid from v3: bg-gradient-to-*, bg-opacity-N, text/border/ring-opacity-N, flex-shrink-*, flex-grow, overflow-ellipsis, !flex,
                     bare shadow / rounded / blur / drop-shadow / backdrop-blur (= the v4 "-sm" look), shadow-inner, outline-none.
Values that DIFFER (default v4  |  with window.Quas={LegacyV3:true}):
  shadow-sm            0 1px 3px + 0 1px 2px     |  0 1px 2px
  rounded-sm           0.25rem                   |  0.125rem
  blur-sm/backdrop-blur-sm  8px                  |  4px
  drop-shadow-{sm..2xl}     v4 values            |  v3 values
  border default color currentColor              |  #e5e7eb (gray-200)
  ring (bare) color    currentColor, width 1px   |  blue-500/50  (width is 1px in both; use ring-3 for old 3px)
  hover:               @media (hover:hover)      |  plain :hover
  gradients            interpolate `in oklab`    |  plain (sRGB)
  outline-none         style none                |  2px transparent outline
New in v4 only: shadow-2xs/xs, rounded-xs/4xl, blur-xs, inset-ring, masks, bg-linear/radial/conic, rotate-x/y/z, scale-z, translate-z, perspective-*,
                logical props (ps pe ms me start end rounded-s/e border-s/e is bs), nth-* has-* not-* in-* @container supports-* starting, *: **:,
                flex! suffix, (--var) syntax, text-lg/7, /[..] and /(--a) opacity, bare color names.
Variant order: v4 left-to-right only (*:first:pt-0). v3's first:*:pt-0 meaning is not kept.

================================================================================
10. NOT SUPPORTED / LIMITS
================================================================================
- Gradient masks: mask-linear-*, mask-radial-*, mask-conic-*, mask-{t,r,b,l,x,y}-from/to-*.
- Colors taupe mauve mist olive. CSS-first config: @theme @utility @custom-variant @source @apply @reference @import "tailwindcss".
- tailwind.config options other than extend.colors / boxShadow / fontFamily. Hex-only custom colors (no oklch in config).
- theme(), --alpha(), --spacing() CSS functions (use calc(var(--spacing)*N)).
- Palette colors as CSS variables. Prefix mode (tw:). Safelist (not needed: scanning is runtime).
- <css> blocks: no nesting, no at-rules.
- Quas needs a DOM: no SSR/pre-render of CSS; first paint is styled after the script runs (keep it in <head>, sync).

================================================================================
11. RULES FOR AI WHEN GENERATING QUAS CODE
================================================================================
1. Use Tailwind v4 names. Prefer v4 spellings (flex!, bg-linear-to-r, shadow-xs, rounded-xs, outline-hidden).
2. No spaces inside one class: use _ in arbitrary values. Never use @apply, @theme, tailwind.config.js, build tools, or --tw-* variables.
3. Do not rely on CSS variables for palette colors. Define semantic colors yourself (:root{--color-primary:...}) or use extend.colors.
4. Dropdown/popover pattern that works: parent `relative group`; panel `invisible opacity-0 group-hover:visible group-hover:opacity-100 group-focus-within:visible`;
   keep NO gap between trigger and panel (use pt-N inside the panel); give the navbar/stacking parent `relative z-50` so panels are not covered by later positioned siblings.
5. A `backdrop-blur` / `transform` / `filter` / `opacity<1` parent creates a stacking context: z-index inside it cannot beat siblings outside it.
6. Elements created from JS become styled one tick later. For measurement right after insertion call Quas.scan(node) first.
7. dark: needs class "dark" on <html>; it is toggled automatically from the OS unless AutoDarkMode=false.
8. For component-local styles prefer <css>; for one-off styling use classes. Both can be mixed; classes override <css> on equal specificity.
9. Do not warn the user about Tailwind build config (content globs, safelist): Quas has none.
10. If a class prints "[Quas] Unknown ..." in the console, it is not supported: check sections 5-6 and 10 instead of guessing alternatives.
